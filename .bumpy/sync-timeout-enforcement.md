Enforce the evaluation timeout as a real boundary. The synchronous evaluator now checks the deadline at completion and after every function, transform, and method call, and charges per-element work in bonsai lambda callbacks, flat literal loops, and spread materialization against the timeout budget, so a lambda-driven loop such as `items.map(.x)` over a large array is pre-empted mid-iteration. Native array methods are checked at return rather than mid-iteration (bounded by `maxArrayLength`), and are otherwise run untouched, so callback index/array arguments, sparse-hole skipping, `thisArg`, short-circuiting, method overrides, and function-valued arguments all behave exactly as they do without a timeout. Array spreads are materialized by index so a `Proxy` or overridden `Symbol.iterator` cannot bypass the accounting or the `maxArrayLength` cap. Deadlines use a monotonic clock, and the timeout machinery is skipped entirely when no timeout is set. Expressions that previously ran past a configured `timeout` inside host calls or large lambda-driven operations now throw `BonsaiSecurityError` with code `TIMEOUT`.
