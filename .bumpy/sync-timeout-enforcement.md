Enforce the evaluation timeout as a real boundary. The synchronous evaluator now checks the deadline at completion and after every function, transform, and method call. When a timeout is configured, array-method callbacks (`map`, `filter`, `reduce`, `sort`, ...) are wrapped to charge the timeout budget on each invocation, so a callback over a large array is pre-empted mid-iteration instead of running to completion; the native method still runs, so callback index/array arguments, sparse-hole skipping, `thisArg`, short-circuiting, and method overrides are unchanged. Both evaluators charge per-element work in lambda callbacks, flat literal loops, and spread materialization against the timeout budget; array spreads are materialized by index so a `Proxy` or overridden `Symbol.iterator` cannot bypass the accounting or the `maxArrayLength` cap. Deadlines use a monotonic clock, and the timeout machinery is skipped entirely when no timeout is set. Expressions that previously ran past a configured `timeout` inside host calls or large array operations now throw `BonsaiSecurityError` with code `TIMEOUT`.
